How it is built (`demo/tap/src/make.js`, `public/make/app.js`,
`public/ui.css`):

- `/api/channels` asks Buffer its own small question each time the Buffer
  step opens: `id service name isDisconnected isLocked isQueuePaused`. The
  question behind `/me` is untouched. If Buffer refuses the new question the
  route gives the channels it already had, as before.
- It writes the account record only when the answer differs from what the
  record holds. My first version (the 00:13 deploy) wrote the record on
  every read; a read that writes can put an older copy of the record over a
  newer one, so I changed it before stopping.
- The page shares one channels request between the video's box and the
  all-videos box. Two requests at once on an expired token would both try
  to renew it, and Buffer cancels a sign-in whose renewal token is used
  twice.
