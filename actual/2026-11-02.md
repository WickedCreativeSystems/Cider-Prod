## 3. Render time — measured, not changed
A 1-script Comic Cover video, headless Chrome for Testing on this
8-core box with no GPU (software H.264), app.js patched in flight:
- baseline: 85 s for 735 frames; drawing the frames took 0.29 s of it.
  It is all the encoder: ~115 ms a frame.
- encoder `latencyMode: "realtime"`: 80 s (−6%).
- 24 fps instead of 30: 56 s for 492 frames (same per-frame cost, fewer
  frames).
- four encoders in parallel, one per quarter of the timeline, chunks
  stitched in order: 119 s. Slower; Chrome's software encoders don't run
  side by side. Dead end, recorded so it isn't tried again.
- 720×1280: 41 s for 675 frames (~61 ms a frame, about half).
So on a machine without hardware encoding the only real levers are size
(halves it) and frame rate (−20%); both change the output. Nothing
shipped; the boss was given the numbers and asked for theirs.
